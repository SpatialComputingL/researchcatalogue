Azure_Kinect_sensor-README

Sensor - Azure skeleton

Live 3D positions of body joints from the Azure Kinect sensors.
Choose the joints you need, each gets its own outlet.

In: none · Out: one CHOP per joint (tx ty tz)

How to use

  1. Add joints (+/-) and pick a joint in each slot (head, hand_l, hand_r, pelvis, ...).
  2. Press Configure.
  3. Hang a null named after the joint off each outlet (null_head, null_handl, ...).
  4. Not in the lab? Turn on Mouse and keep building.

Settings

  • Mouse: off = sensor data, on = joints follow the mouse
  • Mouse orientation: which plane the mouse drives (XZ = across the floor)
  • Add joints: adds or removes joint slots
  • Configure: rebuilds the outlets after changing joints
  • Person: not working yet, leave at 1
  • Fallback origin: joints rest at Position when there is no data

Outputs

  • One outlet per slot: tx ty tz in meters, same order as the slots
  • Axes: X = width, Y = height, Z = depth

Normal, not bugs

  • All values 0: not in the lab, or nobody in view. Turn on Mouse.
  • Mouse orientation greyed out: Mouse is off.
  • Person does nothing: known, see above.
  • Values jump when someone re-enters: tracking re-acquiring. Use Fallback origin or smooth downstream.
  • Removed joints still showing: press Configure.
Azure_Kinect_camera-README

Camera - Azure Kinect

The live camera image of the lab's Azure Kinect sensors.
Image only: the video stream comes from a different PC.
For body positions, use Sensor - Azure skeleton.

In: none · Out: one TOP per sensor

How to use

  1. Pick a stream in Image.
  2. Press Configure.
  3. Hang a named null off each outlet (null_cam_left, null_cam_right, ...) and work from those.

Settings

  • Image: which stream you get (colour, ...)
  • Configure: rebuilds the outlets after changing Image

Outputs

  • Outlet 1, 2, 3: one sensor each, fixed order. Wave at a camera to find out which is which.

Normal, not bugs

  • Black or empty outputs: not in the lab, or the sensors are off.
  • All views look the same: the same empty room from different corners.
  • Image doesn't change after switching Image: press Configure.
  • Unexpected resolution or framerate: set by the sensor and stream. Fit or resample downstream.
virtual_object_viewer-README

Virtual object viewer

Shows tracked points and virtual objects together in one 3D scene,
to check that everything is where you think it is.
It only displays, it changes no data.

In: positions (CHOP) and shapes (POP) · Out: preview

How to use

  1. Wire joint outlets of Sensor - Azure skeleton into the green inputs. Each becomes a sphere.
  2. Virtual objects in the project appear with their own colour.
  3. Pick a Viewport.

Settings

  • Viewport: perspective for a quick check, top for the floor plan
  • Colors: off = grey, on = coloured

Outputs

  • Preview: 3D scene, the wireframe box is the room

Normal, not bugs

  • Everything in one spot: nothing wired, or the sensor isn't running.
  • Spheres frozen: the source is frozen. Check the sensor.
  • A sphere outside the box: position out of range, or outside the sensor's field.
  • Low-resolution preview: it's a node preview. Open a bigger viewer.
virtual_object-README

Virtual object

Puts an invisible shape (sphere, box, cylinder) in the room for other components to interact with.

In: position (CHOP, optional) · Out: shape (POP) and position + size (CHOP)

How to use

  1. Pick a shape in Virtual Object.
  2. Set the size, Position XYZ and Rotate XYZ.
  3. Wire the blue output into Calculations or Virtual object viewer.
  4. Wire the green output into anything that needs the position, e.g. a sound source.

Settings

  • Virtual Object: shape, sphere, box or cylinder
  • Width X, Height Y, Depth Z, Radius: size. Only the fields for the current shape are active.
  • Position XYZ, Rotate XYZ: place in the room (X = width, Y = height, Z = depth)
  • Get pos (shift+m): grab a position instead of typing it
  • Outer shell + Radius: sphere only, a larger outer sphere for a soft edge, used by Fade to sphere
  • Viewport: preview camera only, doesn't move the object

Outputs

  • Blue: the shape as a POP
  • Green: center position tx ty tz and a size value from the radius

Normal, not bugs

  • Size fields greyed out: they belong to another shape.
  • Outer shell greyed out: not a sphere.
  • Preview looks squashed or off-centre: that's the viewport. Switch it.
  • Nothing visible in the room: this only makes the shape. Draw it with the viewer or a projection.
CALC-README

Calculations

Measures how a point or shape relates to another point or shape:
distance, inside or outside, or a fade.
Typical use: a tracked hand and a virtual object.

In: 2 POPs (point or shape) · Out: 1 CHOP

How to use

  1. Connect a point or shape to input 1, e.g. a tracked joint.
  2. Connect a point or shape to input 2, e.g. a virtual object.
  3. Turn on one calculation.
  4. Read the result from the output CHOP.

Settings

  • Distance between points: distance between the centers of both inputs
  • Distance between shapes: distance to the surface of the shape(s)
  • In or outside of a shape: is input 1 inside input 2
  • Fade to sphere: soft value between the inner sphere and the outer shell

Only one can be on. The others grey out until you turn it off.

Outputs

  • center_dist: meters between the centers
  • shell_dist: meters to the surface, negative = inside
  • inside: 1 inside, 0 outside
  • fade: 1 inside the inner sphere, 0 outside the outer shell, smooth in between

Normal, not bugs

  • Fade to sphere greyed out: input 2 is not a sphere with Outer shell on.
  • Wrong distances: the shape is not closed (open side).
  • Box or cylinder distances a bit large near edges and corners: measured from the center outward.
  • Yellow warning inside the component with a point on input 1: harmless.
Ambisonics_sound_ctrl-README

Ambisonics sound control

Places sound sources in 3D space and mixes them for the ambisonics speaker system.
Each source has its own position, size and audio input.

In: one position per source (CHOP) · Out: mix for the speaker system

How to use

  1. Add a source with Add virtual object (+/-). A new inlet appears on the left.
  2. Wire a position into that source's inlet, e.g. a virtual object. Inlets go top to bottom in the same order as the numbered sources.
  3. Point Audio in at the CHOP that carries the sound.
  4. Set Rangegain, or let a virtual object set it.

The network inside is built and wired by a script. Never rewire it by hand.

Settings

  • Add virtual object: adds or removes sources
  • Posin: read-only readout of where the position comes from
  • Rangegain: size and gain of the source. Follows the Radius of a wired virtual object (shown as a bind), otherwise type it in.
  • Audio in: the CHOP or channel with the source's sound. Sample rates are matched to Dante (48 kHz) automatically.

Outputs

  • Ambisonics mix of all sources for the speaker system
  • 3D view: one sphere per source, sized by Rangegain

Normal, not bugs

  • Posin shows the middle of the room: nothing wired into that source's inlet.
  • Rangegain is a plain number instead of a bind: nothing wired in, or it isn't a virtual object.
  • A new or removed source takes a moment to appear: the script rebuilds about once a second.
  • A manual rewire inside the component reverts: the script puts the internal chain back.
wall_projection-README

Wall projection

The output to the lab's wall projectors.
Opens the projection window and tells you the resolution your image must have, at home and in the lab.

In: 1 to 3 TOPs · Out: projection window and resolution (CHOP)

How to use

  1. Wire the resolution CHOP (resX, resY) into your own source TOP. Don't type numbers.
  2. Wire your images in: input 1 left, 2 center, 3 right.
  3. Choose a mode and press Configure.
  4. Open Window to project, Close Window while editing.

Settings

  • License: off = home resolution, on = full lab resolution
  • Panoramic projection: one wide image across the wall, uses input 1 only
  • Single projection: output to one projector only
  • Both off: three screens, left, center, right
  • Fit Input: what happens to an image of the wrong size
  • Output Resolution: readout of the current resolution
  • Configure: rebuilds after changing mode
  • Open Window, Close Window: opens or closes the projection

Outputs

  • Resolution CHOP: resX, resY for your source

Normal, not bugs

  • Small resolution: License is off (home setting).
  • Inputs 2 and 3 do nothing: Panoramic is on.
  • Stretched, cropped or black bars: your source isn't following the resolution CHOP.
  • Content on the wrong wall: order is left, center, right.
  • Nothing visible after a change: Configure, then Open Window.
floor_projection-README

Floor projection

The output to the floor projector.
Works like Wall projection, but the floor is square-ish, not wide.

In: 1 TOP · Out: projection window and resolution (CHOP)

How to use

  1. Wire the resolution CHOP (resX, resY) into your source TOP.
  2. Put a Fit TOP before the component:
moviefilein → fit → floor_projection
  1. Press Configure.
  2. Open Window to project, Close Window while editing.

Settings

  • License: off = home resolution, on = full lab resolution
  • Fit Input: what happens to an image of the wrong size
  • Configure: rebuilds after changing settings
  • Open Window, Close Window: opens or closes the projection

Outputs

  • Resolution CHOP: resX, resY for your source

Normal, not bugs

  • Wall content looks wrong: different aspect ratio. Add a Fit.
  • Small resolution: License is off.
  • Image "upside down": the floor has no up. Orient to where the audience enters, and note it.
  • Nothing visible after a change: Configure, then Open Window.
Spatial Computing Lab Description

LUCA School of Arts (LUCA)
Partner: FilmEU
Coordinator: Jan Duerinck
Contact: jan.duerinck@luca-arts.be
Website: https://www.researchcatalogue.net/

Focus: Augmented/mixed reality, spatial computing, and interactive media

Primary Goals: Advance interdisciplinary research in XR and spatial computing; strengthen doctoral and practice-based research.

Lab Description: The Spatial Computing Lab (LUCAscl*) at LUCA School of Arts explores real-time spatial interaction, augmented and mixed reality, and immersive sound. Integrating panoramic video, depth sensors, and tactile interfaces, it fosters artistic research into the dynamic relations between digital and physical space. The lab aims to develop critical, experimental, and participatory approaches to spatial computing and media art. As part of WIRE, it contributes to interdisciplinary research across XR, installation practices, and interactive design. Its goals include strengthening collaborations, expanding its technological capabilities, and building a sustainable framework that supports doctoral and practice-based research within LUCA and FilmEU.
